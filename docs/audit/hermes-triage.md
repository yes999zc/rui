# Hermes 第三方审计分诊台账（24 个 issue，2026-10-26）

> 来源：第三方审计 Hermes 在三个仓提的 24 个 issue（rui 17 / rui-dot2-bridge 5 / rui-xiaoai-bridge 2）。
> 方法：每条独立复现或代码取证（file:line + 命令 + 实际输出），**不采信 issue 的结论**；
> 逐条回答三关——核实（成立/误报/部分成立）、影响面（会不会伤既有行为）、定级与处置。
> 基线：rui `cd2d0a2`（0.7.2 + 0.7.3 测试卡）、dot2 `18ad114`（1.3.1）、xiaoai `6899c49`（0.2.1）。
> 夜间约束：所有「听感/真机」验证留白天，本台账里标 **daytime**。
>
> **结论先行**：24 条里 **0 条维持原 P0**（3 条 P0 都有前置条件，降为 P1）；2 条部分误报；
> 1 条与另一仓重复（xiaoai#1 = rui#25，rui 拥有修复）。真正进 0.7.4 的只有 4 组 P0/P1。

## 0. 分级口径（我们的级别）

| 级别 | 含义 | 进哪个版本 |
|---|---|---|
| P0 | 默认部署下即可被利用/直接坏掉、无前置条件 | 立即（0.7.4） |
| P1 | 有明确前置条件，但会静默坏功能 / 丢数据 / 泄漏凭据 | 0.7.4 或 0.7.5 |
| P2 | 边缘条件、体验或加固缺口 | 0.7.7 / 桥 1.3.2-1.3.3 |
| P3 | 文档/一致性/低概率，记录即可 | backlog 或关闭+理由 |

## 2. 风险最高的四条（先核，改错代价大）

1. **#27 cue 回声（否决 Hermes 修法）**
   - 复现：生产几何 `skip=790/hold=1740`，cue 期间麦克风静音，回复在 790/800/850 ms 开口 → 余弦 0.98/1.00/0.783，切掉 590 ms 回复头（captured 1.81 s→1.06 s）；回复 ≥900 ms → 0.66 不动（`vad.py:32` = 800 ms 上界）。
   - Hermes 的「去均值」修法：真实衰减回声 -26 dB / 噪声 -30 dB 场景 0.855→**0.434**；更差 SNR 直接 **-0.129** → 正是它想防的「在呢」泄漏。**否决**。
   - 我们的最小修法：`heard_any=False` 且命中落在缓冲区内时**不切除**（对齐「设备硬静音」的设计），不动 0.75 门限、不动生产几何。测试补真实语音信号（现测试合成音余弦 0.596，天然不过门限 → 假通过）。
2. **dot2#2 无 token 控制面**：fail-open 真实（`device_link.py:272-275`、bind `0.0.0.0` 且从未传参），但文档部署强制 token（README:57/70/184、deploy-nas.md:17-21），无 secrets 时 `_tls_context` 直接拒绝启动。→ P2 加固，不是「默认部署裸奔」。
3. **dot2#3 /loudness**：`trim_db: NaN` → 200 → 0/480 非零样本 → 持久化 → **重启后仍静音**（已复现）；但 loopback + 默认关闭。→ P2，1.3.2 必修（校验 + 原子替换 + 坏文件回落）。
4. **#32 audio_defaults**：结构缺口成立，但 Hermes 的因果链在本仓断了（无 rs03qr.yaml、无 rate!=48000 校验、lx06 manifest 无 playback 块、ack 窗口与全局同值）。→ 只写文档 + doctor 检查，**不按 pip 语义改死**。
