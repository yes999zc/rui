## 症状

真机上到点提醒只念一句「起床」：房间里的音箱突然说一个动作名，人不知道这句话
为什么来、是谁说的。原因是 `_reminder_line()` 的在线分支直接 `return item.text`，
把创建提醒时存下来的动作文本原样播了出去。

## 文本规范化（`src/rui/web/api/app.py::_reminder_due_line`）

设置提醒时用户会说「提醒我…」，播报时这句话已经由模板承担，所以存下来的文本要先
规范化，避免念出「时间到了，叫你起床。」：

1. 只剥**前导**触发词：`提醒我 / 叫我 / 让我 / 叫你`（触发词与动作之间允许空白）。
   `叫你` 与 `叫我` 是同一个播报对象，来自创建路径存下来的文本；只影响开头一次。
2. `strip()`，再去掉**结尾**的句末标点 `。！？!?`（可连续多个，如 `!?`），
   由模板统一补唯一一个「。」，不出现双标点。
3. 规范化后为空（空字符串 / 纯空白 / 只有触发词）时，退化为
   `时间到了。`：模板渲染会留下悬空逗号（`时间到了，。`），helper 删掉这个逗号分句，
   不朗读标点，也不抛异常。
4. 中间的逗号、长文本一律保留，不做截断。

归一化只用于**在线播报**。离线分支仍把 `item.text` 原样填进 `reminder.offline`
（该模板的措辞与 0.8.4 逐字相同）。

## 风险 / 未做

- **真机未验证**：本批只有单测；TTS 对「时间到了，」「。」的停顿/语气未实测。
- 触发词剥离是文本层规则，不做语义判断；若某条提醒文本本身以 `叫你…` 开头且
  「你」有实义（如「叫你爸回电话」→「爸回电话」），会被剥掉。这类文本应改为
  不带触发词的写法（提醒文本存的是动作）。**已知取舍**，不扩成 NLP。
- 话术可被 console 覆盖：`reminder.due` 的覆盖模板若不含 `，`，空文本时直接
  返回该模板，不再做任何标点清理。
- 不改调度、抢占、离线回落、房间路由（0.8.4 task-31/32 的逻辑原样）。
