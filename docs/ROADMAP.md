# ROADMAP — house-ear

> 一份文件回答三个问题：**到哪一步了、下一步做什么、什么叫做完了。**
> 每一步的门槛都是**可复现的实测数字**，不是「已完成」。数字和出处写在
> `docs/HANDOFF.md` 与 `docs/audio-latency.md`。

## 0. 什么叫 v1 完成（发布门槛）

四个条件全部满足才算 v1，缺一条都叫「开发中」：

1. **NAS 冷装 30 分钟到第一句回应**：全新机器、`docker compose up`、说一句话听到回答。
2. **80% 音量放歌时，20 次唤醒成功 ≥19 次**（真机，已知音量）。
3. **打断：用户开口后 ≤300 ms 完全静音**（服务端停推 + 设备缓冲耗尽，分开量）。
4. **公开仓可用**：无私人密钥/路径/内网 IP；README 能让陌生人装起来；MIT。

## 3. 明确不做（这一版）

- 多房间 / 多设备同时出声（一台设备同一时间只有一个播放 owner）
- 唤醒词自训练（换词 = 换 keywords 行，不是换流水线）
- 云端 ASR 做主路（本地优先，云端只兜底）
- 通用语音助手框架（只为这一个家庭 + 这台音箱服务）

## 4. 每次改动的规矩

1. 一步一提交；提交信息写「改了什么 + 实测到什么」。
2. 没有数字的「已完成」不算完成；没有门槛的步骤不进路线图。
3. 老项目解过的问题先抄结论，新需求自己设计；**参数优先参考老项目**。
4. 能为并行就派子 agent，主线只留需要判断和需要真机的部分。
5. 阶段结束顺手更新本文件与 `docs/HANDOFF.md` 的现场状态。
