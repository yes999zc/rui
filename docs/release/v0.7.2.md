## 已知限制（不阻塞发布）

1. **cue 回声的边界情形**：冷启动且不削波且设备滞后 >800 ms、或用户与 cue 重叠 <110 ms 时，cue 仍可能进入 ASR（task-17 的 AEC-lite 已 park，未合入）。
2. **`runner.abort()` 仍是全局单标志**：A 房唤醒会中止 B 房正在合成的回复（runner 单会话限制；按房隔离目前只在 arbiter 层）。
3. **已播出的告别尾音无法追回**：只能阻止后续 chunk，彻底消音需「本机 TTS 参考消减」。
4. **唤醒词不按房间隔离**；`DOT2_CONTROL_PORT` 是全局 env，加第 2 台 Dot2 前必须清。
5. **多设备并发未测**（音量/指示灯/四台同时在线）——见 HANDOFF「待设备」段。
6. `uv.lock` 内仍写旧版本号（0.2.0），不影响运行，记入 post-release backlog。

## English（release notes 摘要 / for the GitHub release）

**rui 0.7.2 · rui-dot2-bridge 1.3.1 · rui-xiaoai-bridge 0.2.1** — three MIT-licensed repos, released together.

### What changed in rui 0.7.2

- **The wake acknowledgement cue no longer reaches ASR.** The gate matches the cue envelope across the skip window and the hold buffer, learns the device's playback lag, and requires silence right after the cue so a TTS reply is never mistaken for it. Device A/B: cue leakage 0/10 (previously 13 of 26 turns).
- **Playback and turn state are scoped per room.** One room playing music used to reject every other room's wake with `lost_playing` (18 rejections in six minutes of two-room sampling); cross-room wakes are now admitted, while `cross_echo` still guards a second plane inside the playing room.
- **Our own stale speech is dropped when a wake arrives.** Queued goodbye chunks are flushed on an accepted wake, late `PLAY_PCM` is blocked until that turn's utterance lands, and every gate close path clears the block so reminders keep working after a silent wake.

### Bridges

- `rui-dot2-bridge 1.3.1`: no behavioural change; `rui_compat` stays `>=0.6.0 <0.8.0`, validated against 0.7.2 (wake 30/30, commands 26/30, barge-in 8/8, short commands during music 10/10).
- `rui-xiaoai-bridge 0.2.1`: the repo is now public after a full-history secret scan (0 tokens/keys, 0 internal IPs, 0 personal paths, 0 MACs); secret scanning and push protection are enabled.

### Known limitations

- Cue echo can still reach ASR on a cold start with no clipping and >800 ms device latency, or when the user overlaps the cue by less than 110 ms.
- The dialogue runner is single-session: a wake on one device aborts a reply being synthesised for another.
- A goodbye already spoken cannot be recalled; only queued chunks are dropped.
- Wake words are not isolated per room yet; concurrent multi-device behaviour is untested.
