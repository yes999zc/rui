# rui v0.7.8 — 发布说明

日期：2026-10-27
范围：`rui` **0.7.8**（核心仓）；`rui-dot2-bridge` **1.3.1** 与 `rui-xiaoai-bridge` **0.2.2** 无代码改动、不 bump（0.7.6 把 LX06 语义测试挪进桥仓是测试搬迁，不改插件行为）。

> 主题：**四张卡合并成一次发版**——安装路径 TLS（0.7.5）、两台平面可见性（0.7.5）、
> 小爱真正摘出核心（0.7.6）、控制台审计 + 默认切 v2（0.7.7/0.7.8）。**API 与契约窗口不变**
> （`C-002/1`，`>=0.6.0 <0.8.0`），没有 schema 迁移。
> 镜像 digest 记录在 GitHub release body 与 `docs/HANDOFF.md` 的发布表；本文件不重复，
> 避免 tag 树内出现占位值。GitHub release body 即本文件（中英双语）。

## 版本口径

**0.7.5–0.7.7 的开发合并进 0.7.8，未单独发版；原因是它们的验收项依赖 0.7.8 的完整代码与真机窗口。** 具体说：Done 6 真机、内置 vs 外置双跑对比、升级与回滚，都要等 0.7.8 的代码齐了才能一次做完；事后补 tag 等于假装「发版时已验证」。**0.7.8 是唯一的验收节点**，本文件与 CHANGELOG 的 0.7.8 段一起记录这四块。

## 行为变更

| 场景 | 0.7.4（上一发布） | 0.7.8 |
|---|---|---|
| 两台设备，默认 `multi_device.enabled=false` | 只起配置里第一台的平面，`/health` 只有聚合 `audio_plane` | 行为不变，但 **`/health.planes` 逐台给出 `state` 与 `reason`**；`rui doctor` 在「2 台且 multi_device 关」时 WARN 并给修复句 |
| dot2 开 `tls_port` / `listen_port` 但缺 `secrets/server.pem` / `server.key` | `audio_plane=false` + `missing TLS material` | 行为不变；0.7.5 把证书路径做进 `examples/two-speakers`（`./secrets` 挂载 + `scripts/make_dev_tls.sh`），三仓安装提示同步 |
| 第三方设备清单未声明 `wake_words_residual`（0.7.6 新增字段） | — | **已知行为变更**：不再 early-yield 设备自己的 vendor 短语，只靠 `is_echo` / `is_noise`；内置 lx06 清单声明三条，行为不变 |
| 配置写 `adapter: xiaoai` | 内置插件可用 | 读入时重写为 `lx06` + 弃用 WARNING（`/health.adapter_plugins.warnings`、设备级 `legacy_adapter_spelling`）；需要外置 `rui-xiaoai-bridge` 插件 |
| `GET /`（配置里**没有** `console` 键） | 200 旧壳（默认 `legacy`） | **302 → `/v2/`**（默认 `v2`，保留 query） |
| `GET /`（`console: legacy`） | 200 旧壳 | 200 旧壳（不变；这是**一版回滚**） |
| 老链接 `/panel/<id>`（11 条）、`/setup`、`/secrets`、`/diagnostics`、`/channels` | 200 旧壳 | **302 → 对应 v2 页面**；`providers` / `system` / `channels` 三条 v2 暂无对应页 → `/v2/?from=<旧路径>` |
| 旧控制台位置 | `/`（`legacy` 模式下 `/legacy` 也可以） | **`/legacy`**（200，顶部中英弃用横幅，**0.8.0 移除**） |
| `/health.console` | `legacy` | `v2`（默认；显式 `legacy` 时仍报 `legacy`） |
| `/api/v1/*`、`/api/v2/*`、`CONFIG_VERSION`、契约窗口 | — | **不变**（0.7.5 的 `/health.planes` 是 additive A-8） |

> **升级注意（必须知道）**：升级到 0.7.8 后，**配置里没写 `console` 键的老部署会静默
> 变成 v2 入口**（`/` → `/v2/`），无需改配置、也无法从配置文件看出变化——看
> `/health.console` 或根地址的 302。想保持旧入口，写 `web.console: legacy` 后重启。
>
> `?from=` **目前只是标记**：v2 不读取、不提示，`/v2/` 的 SPA redirect 会带着 query 进
> `/v2/devices`；所以 `providers` / `system` / `channels` 三条老书签最终停在设备页
> （审计 `console-functional.md` §8.9）。

## 已知限制（不阻塞发布）

0.7.5–0.7.8 相关：

1. **自签证书不保证真机链路**：只证明音频平面能启动；设备以固定 ServerName 校验，
   原 controller 证书无法重建，丢失时需重新配网（`docs/audit/tls-required-2026-10.md`）。
2. **双设备默认仍只起第一台平面**：`multi_device.enabled: true` + `max_planes >= 2`
   才会为每台起平面；`/health.planes` 与 doctor 现在会明说，不再静默。
3. **`wake_words_residual` 未声明的第三方清单**可能让设备自己的 vendor 短语进入回合
   （内置 lx06 已声明三条，不受影响）。
4. **`providers` / `system` / `channels` 在 v2 没有对应页**：老链接落
   `/v2/?from=<旧路径>`，`?from=` 只是标记（v2 未消费），最终停在设备页 `/v2/devices`。
5. **v2 空态仍有两处 `/legacy` 出口**（`DevicesView.vue` / `RunView.vue`）：这是“v2 做
   不了、去旧壳做”的明确出口，`/legacy` 带弃用横幅；0.8.0 删旧壳时必须一并处理。
6. **0.7.7 审计的 12 行未验证**（6 类，原因见审计 §11）：需真机/需特定异常环境，本轮
   没有构造，不做推断。
7. **条件性 500**：音乐凭据路径不可写时 `PUT /api/v1/music/credentials` 返回 **409**（0.7.8 已修，原来是 500）（应为 4xx），
   见审计 §8.1。

沿用 0.7.4 的运行时限制（cue 回声边界、单会话 runner、告别尾音不可追回、唤醒词不按房间
隔离、多设备并发未测）与 0.7.7 的 v1 功能缺口（话术编辑器、供应商卡片/试听、音乐播放
6 按钮、system/web/security 字段、渠道、工具注册表、设备探测、MCP/HA 写入）——均未在
0.7.8 改变。

## 升级与回滚

- 升级：`RUI_IMAGE=ghcr.io/yes999zc/rui:0.7.8 bash deploy/install.sh`，或把 override 的
  `image:` 改为 `ghcr.io/yes999zc/rui:0.7.8` 后 `docker compose up -d`。
- **无 schema 迁移**；`rui_compat` 仍为 `>=0.6.0 <0.8.0`；dot2 保持 1.3.1，xiaoai 为 0.2.2。
- **升级检查**：
  1. 两台设备要同时出声 → 配置加 `multi_device: {enabled: true, max_planes: 2}`。
  2. 用 LX06 → 确保外置 `rui-xiaoai-bridge` 插件已挂到 `/opt/rui-plugins`（镜像需同时带
     `RUI_ADAPTER_PLUGINS` 与 `PYTHONPATH=/opt/rui-plugins`）；配置里的
     `adapter: xiaoai` 会自动迁移为 `lx06` 并告警。
  3. dot2 的 `tls_port` 开启 → 把 `server.pem` / `server.key` 放进挂载的 `./secrets`，
     没有就 `bash scripts/make_dev_tls.sh`（自签不保证真机接受）。
  4. 确认入口：`curl -s http://127.0.0.1:8080/health | jq -r .console` → `v2`；
     `curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' http://127.0.0.1:8080/`
     → `302 …/v2/`；老书签如 `/panel/logs` 也应返回 `302` 到 `/v2/logs`。
- **回滚到旧入口（保留 0.7.8 镜像）**：配置写 `web.console: legacy` 后
  `cd ~/rui && docker compose up -d --force-recreate` —— `/` 与 15 条老链接恢复 200 旧壳，
  `/health.console` 报 `legacy`。操作细节见 `docs/deploy.md` §3.8。
- 回滚到旧镜像：把 image 改回 `rui:0.7.4`（或生产组合 `rui-dot2:1.3.1`）后
  `docker compose up -d --pull never`；配置无需回退（0.7.x 都读 `console` 键，0.6.x
  忽略它并按旧壳运行）。

## English (release notes summary / for the GitHub release)

**rui 0.7.8** — MIT-licensed. `rui-dot2-bridge` **1.3.1** and `rui-xiaoai-bridge`
**0.2.2** are unchanged (the 0.7.6 test move does not change plug behaviour).

**Theme: four cards in one release** — the TLS install path (0.7.5), per-device plane
visibility (0.7.5), the LX06 plug leaving core (0.7.6), and the console audit plus the
v2 default (0.7.7/0.7.8). **No API or contract change** (`C-002/1`, window
`>=0.6.0 <0.8.0`), no schema migration.

### Versioning

**0.7.5 / 0.7.6 / 0.7.7 get no tag of their own; they ship inside 0.7.8.** Their exit
conditions (Done 6 on hardware, the built-in-vs-external dual run, upgrade and
rollback) all need the complete 0.7.8 tree and one hardware window; tagging them after
the fact would claim verification that never happened. **0.7.8 is the single
acceptance node.**

### What changed

- **0.7.5 — TLS in the install path.** `examples/two-speakers/compose.yaml` mounts
  `./secrets` at `/opt/rui-secrets` (`DOT2_SECRETS_DIR`), `scripts/make_dev_tls.sh`
  self-signs `server.pem`/`server.key`, and all three repos' install prompts gained the
  TLS step. With dot2's `tls_port` on, certs are mandatory: missing material gives
  `audio_plane=false` with `missing TLS material`. Three matrices × 2 runs measured
  (`docs/audit/tls-required-2026-10.md`): no certs → false; no TLS + empty
  `RUI_DEVICE_TOKEN` → false; certs + both tokens → true and `dot2 link: wss listening
  on 8871`. Self-signed only proves the plane starts — the device still has to trust
  the CA, and the original controller certificate cannot be recreated.
- **0.7.5 — per-device plane visibility.** `GET /health.planes` returns one row per
  enabled device (`state` = `running|error|not_started`, `reason` =
  `multi_device_disabled|plane_not_started|audio_not_started`, `error`); `audio_plane`
  stays the aggregate. `rui doctor` warns when 2+ devices are enabled and
  `multi_device` is off, and `config.example.yaml` carries the two-line example
  (C-002 A-8, 7 new tests).
- **0.7.6 — the LX06 plug leaves core.** `plugs/xiaoai/` and
  `src/rui/adapter_aliases.py` are gone; the Dockerfile no longer `COPY plugs`, and
  `/opt/rui-plugins` is owned and validated writable at build time. `adapter: xiaoai`
  is migrated on load to `lx06` with a deprecation warning
  (`/health.adapter_plugins.warnings`, device-level `legacy_adapter_spelling`). The
  vendor wake-word fallback is data-driven through the new optional
  `devices[].wake_words_residual`; **known behaviour change:** a manifest that omits it
  no longer early-yields vendor phrases (built-in lx06 declares three). 54
  device-semantics tests moved byte-identically to the bridge repo (core 1655/17 →
  1612/6; bridge 87 passed / 11 skipped). Core grep gate
  `xiaoai|lx06|小爱|4412` is 0 hits outside `legacy_adapters.py`.
- **0.7.7 — console audit.** 172 interaction rows / 159 usable / 12 unverified /
  0 unusable (172 = 159 usable + 1 copy-error row + 12 unverified + 0 unusable), four
  copy/validation fixes (setup first-run copy, stale legacy-console
  hint, dead `v2.config.stub*` keys, English validation messages for device writes).
- **0.7.8 — the v2 console becomes the default.** A fresh install — and **an existing
  `config.yaml` that never wrote a `console` key — now silently serves v2 at `/`**
  (302 to `/v2/`, query preserved). The 15 old console links answer 302 (`providers`,
  `system`, `channels` land on `/v2/?from=<old path>`); the old shell is `/legacy`,
  deprecated with a bilingual banner and removed in 0.8.0. `web.console: legacy` is the
  one-release rollback.

### Evidence

- house-ear **1642 passed / 6 skipped**; `ruff check .` green; frontend
  `npm run typecheck && npm run build` green; `git diff --check` clean.
- Gates: 0.7.5 tasks 9/10/11 PASS + VERIFIED; 0.7.6 tasks 12/13/14 PASS + VERIFIED;
  0.7.7 audit PASS + VERIFIED; 0.7.8 task-17 reviewer-d **PASS** + verifier-tests
  **VERIFIED** (`efab571`); 15/15 old links 302 with a 200 v2 shell after the hop, both

### Known limitations

- Self-signed TLS only proves the plane starts; whether the speaker accepts it depends
  on its trusted CA (the original controller certificate cannot be recreated).
- The default `multi_device.enabled=false` still starts only the first configured
  device's plane; `/health.planes` and `rui doctor` now say so instead of staying silent.
- A third-party manifest that omits `wake_words_residual` may let vendor phrases into a
  turn (built-in lx06 declares three, so it is unaffected).
- `providers`, `system` and `channels` have no v2 page in 0.7.8; their old links stop
  at `/v2/devices` with `?from=` in the URL (**marker only, not consumed** — audit §8.9).
- Two v2 empty states still link to `/legacy` on purpose; they must be handled when the
  old shell is removed in 0.8.0.
- 12 audit rows stay unverified (six categories, reasons in the audit §11); music
  credentials on a non-writable path still return 500 (conditional).
- Unchanged from 0.7.4: cue-echo edges, single-session runner, non-recallable goodbye,
  per-room wake words, concurrent multi-device untested. Unchanged v1-only gaps: phrase
  editor, provider cards/audition, music playback buttons, system/web/security fields,
  channels, tool registry, device probe, MCP/HA writes.

### Upgrade and rollback

- Upgrade: `RUI_IMAGE=ghcr.io/yes999zc/rui:0.7.8 bash deploy/install.sh`, or pin
  `image:` to `ghcr.io/yes999zc/rui:0.7.8` and `docker compose up -d`.
- No schema migration; `rui_compat` stays `>=0.6.0 <0.8.0`.
- Before upgrading:
  1. Add `multi_device: {enabled: true, max_planes: 2}` if two speakers must play at
     once.
  2. For LX06, mount the external `rui-xiaoai-bridge` plug under `/opt/rui-plugins`
     (`RUI_ADAPTER_PLUGINS` + `PYTHONPATH=/opt/rui-plugins`); a config with
     `adapter: xiaoai` is migrated to `lx06` with a warning.
  3. When dot2's `tls_port` is on, put `server.pem` / `server.key` in the mounted
     `./secrets` (or run `scripts/make_dev_tls.sh`; self-signed does not guarantee the
     speaker accepts it).
  4. After upgrading, confirm the entry point: `curl -s localhost:8080/health | jq
     .console` is `v2`, `curl -sI localhost:8080/` returns 302 to `/v2/`, and an old
     bookmark such as `/panel/logs` returns 302 to `/v2/logs`.
- **Rollback to the old entry point (keeping 0.7.8)**: set `web.console: legacy` and
  run `cd ~/rui && docker compose up -d --force-recreate`. `/` and the 15 old links return the old shell again and
  `/health.console` reports `legacy`.
- Rollback to an older image: pin `rui:0.7.4` (or the production `rui-dot2:1.3.1`
  combination); the config needs no change (0.7.x read the key, 0.6.x ignores it and
  runs the old shell).
