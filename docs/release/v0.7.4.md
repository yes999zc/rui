## 行为变更

| 场景 | 0.7.3 | 0.7.4 |
|---|---|---|
| 请求体 > 1 MiB（默认；`RUI_MAX_REQUEST_BYTES` 可调） | 进入解析/鉴权路径，无上限 | **413** `{"detail":"request body too large"}`（Content-Length 或流式累计超限） |
| 无 token + 小 body | 401 | 401（不变） |
| 有效 token + 非法 JSON | 422 | 422（不变） |

其余 **HTTP 状态码/handler 契约行为**不变；31 个 v1 handler 的解析位置未动。

## 已知限制（不阻塞发布）

沿用 0.7.3 的运行时限制：

1. **cue 回声的边界情形**：冷启动且不削波且设备滞后 >800 ms、或用户与 cue 重叠 <110 ms 时，cue 仍可能进入 ASR。
2. **`runner.abort()` 仍是全局单标志**：A 房唤醒会中止 B 房正在合成的回复。
3. **已播出的告别尾音无法追回**：只能阻止后续 chunk。
4. **唤醒词不按房间隔离**；`DOT2_CONTROL_PORT` 是全局 env。
5. **多设备并发未测**（音量/指示灯/四台同时在线）。

0.7.4 新增（来自本轮实现边界）：

6. **微信流式超限分支未被测试覆盖**：测试只覆盖了 `Content-Length` 超限；无长度头的累计超限路径有实现、无单测。
7. **`getupdates` 响应未设上限**：轮询响应仍由 httpx 整体读入，未加字节上限（语音下载已加）。
8. **413 响应缺 `Permissions-Policy`**：已带 `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` / `Cache-Control`，未带 `Permissions-Policy`（该头对 JSON 无实际作用）。

## English（release notes 摘要 / for the GitHub release）

**rui 0.7.4 · rui-dot2-bridge 1.3.1 · rui-xiaoai-bridge 0.2.2** — three MIT-licensed repos.

**Theme: P0/P1 fixes.** 0.7.4 adds exactly one status code, **413** for an oversized
request body; the 401 and 422 semantics are unchanged.

### What changed in rui 0.7.4

- **Request bodies are bounded before parsing (#18).** A pure ASGI middleware rejects
  a declared `Content-Length` above 1 MiB (configurable via `RUI_MAX_REQUEST_BYTES`)
  with 413, and counts streamed bodies so a chunked upload cannot grow memory past
  the cap. Missing/bad token stays 401 and invalid JSON with a valid token stays 422.
- **`_greet` no longer blocks the event loop (#17).** The socket wait yields every
  10 ms, and the handshake `read_frame` uses one absolute deadline for header and
  payload. Transient socket errors are retried within the greet budget; if the child
  exited, the error keeps its exit code and the last stderr lines.
- **The WeChat channel survives one bad message (#28).** The getupdates cursor is
  saved in `finally`, voice downloads are capped at 10 MiB, and pilk/ffmpeg decoding
  runs in `asyncio.to_thread`.
- **Reconnecting resets the player (#25 / xiaoai#1).** Replacing the speaker socket
  resets `_playing` / `consumed` / `sink_generation`; a suspended old `play()` cannot
  resurrect it, and events from the replaced socket cannot advance the new player.
  Mirrored in `rui-xiaoai-bridge` **0.2.2**.

### Evidence

- house-ear **1652 passed / 17 skipped**; rui-xiaoai-bridge **13 passed**;
  rui-dot2-bridge **145 passed**; `ruff` green in all three.
- Each fix has a reverse-mutation check: removing its guard makes the targeted test
  fail.

### Known limitations

Unchanged from 0.7.3 (cue-echo edges, single-session runner, non-recallable goodbye,
per-room wake words, concurrent multi-device untested). New: the WeChat streamed
over-limit path has no test (only `Content-Length`), `getupdates` responses have no
size cap, and 413 omits `Permissions-Policy` (the other security headers are present).
