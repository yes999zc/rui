# rui 0.8.5

**2026-10-28** · [完整 changelog](../../CHANGELOG.md) · 插件保持 **dot2 1.3.4 / xiaoai 0.2.3**，`rui_compat` 不变（`>=0.8.1 <0.9.0`）· **本版本只发 tag/release，不部署生产**（生产仍是 0.8.4）。

本批是 0.8.5 攒批（A–G）：一条能听懂的到点提醒、一句真正被固定句式接住的「一分钟后」、17–20 字短回复不再被逗号切开，以及不再挂死的 CI 3.11。

## 修复 / 行为变化

1. **到点提醒有前后文**：在线播报改为「时间到了，{text}。」；存储文本的前导「提醒我 / 叫我 / 让我 / 叫你」先剥掉，句末标点归一到唯一「。」，空文本退化为「时间到了。」。离线分支措辞一字未改。→ 不再出现只念「起床」。
2. **分钟级相对时间由固定句式受理**：「一分钟后提醒我喝水。」现在直接进固定入口（与工具路径共用 `parse_at("+Nm")`），不再绕 LLM 工具。**动作必须单句**：带第二句的「…。我是小志。」仍交 LLM（不污染提醒文本、保持 0.8.4 的来源房间行为）。小时/天/周/刻/区间/`过N分钟`/`半小时`/多句仍交 LLM。两条路径共用同一个 `_reminder_room()`。
3. **17–20 字含逗号回复合并为一次 TTS**：逗号只在当前句已缓冲 **>20 字**时才作为切分点（`SOFT_MERGE_MAX_CHARS=20`）。17/18/19/20 字（逗号在第 16 字）实测由 2 次 TTS 变 1 次；句末标点仍立即释放，13 字单句/19 字双句/40 字长句行为不变；>20 字仍在逗号处提前发声（最多晚 5 字）。
4. **CI `test (3.11)` 死锁修复**：CPython 3.11 `asyncio.wait_for` 会吞掉同一 tick 到达的取消（[python/cpython#96764](https://github.com/python/cpython/issues/96764)，3.12 重写后未回移）；`_speak_loop` 的 `wait_for(queue.get(), 0.5)` 改为 `asyncio.timeout(0.5)`（同超时、同 `TimeoutError`、stdlib），并给 `test` job 加 `timeout-minutes: 20` 防再挂。测试代码零改动。
