# rui 0.5.1

**2026-10-25** · [Full changelog](../../CHANGELOG.md) · [Compare v0.5.0...v0.5.1](https://github.com/yes999zc/rui/compare/v0.5.0...v0.5.1)

0.5.1 is a patch release for the **install path**, found by dot2's clean 0.5.0 install.
There is **no runtime, config-schema, API or plug-contract change**: the audio/arbitration
code is identical to 0.5.0, so an existing 0.5.0 deployment does not need this upgrade
unless it is reinstalled from scratch. New installs and downstream image builds benefit
immediately.

## Highlights

### 1. `install.sh` stops executing its own comments (dot2 #13)

The `.env` template was written with an unquoted heredoc, so backticks in the template
comments were command-substituted during install. On a machine whose current directory
happened to be another compose project, that stray text could start it. The template is
now a quoted heredoc (`<<'ENV'`) and the per-install values are appended with `printf`, so
the written file is byte-identical to the template and nothing in it can run.

The installer also no longer prints the console token to stdout: setup generates it
without echoing, the installer still saves it to `console-token.txt` (0600), and
`rui token` remains the explicit way to read it back. Tests extract and execute the real
`[3/5]` block with a fake `docker` and assert the bytes, the 0600 mode, that a canary
command is never executed, and that the token never appears on stdout.

### 2. `fetch-models` can no longer fail silently (dot2 #14)

A transient hf-mirror 429 used to abort the ASR download with only a WARNING while the
installer exited 0, leaving a green container with no ASR. Now:

- downloads retry 429/5xx up to 4 attempts (1 s -> 2 s -> 4 s, 8 s cap); 404/401 fail fast
  so the next mirror is tried;
- the installer records the failure, still starts the service so the wizard is reachable,
  then prints remediation and exits non-zero; `RUI_SKIP_MODELS=1` is the documented
  opt-out;
- `rui doctor` gained a `models` row (local sherpa ASR model + tokens, configured VAD file,
  KWS `tokens.txt`); missing models report `degraded` instead of being visible only in the
  install log. `/health` keeps its old fields and stays green on a zero-device fresh boot.

### 3. README: agent-assisted install and refreshed screenshots

The README now has a copy-paste prompt (zh + en) for a command-capable agent: read the
public docs, install with the official script at a pinned tag, ask the operator for the
required settings and keys, never log secrets, then verify with `rui-healthcheck` and one
real turn. The three public screenshots were re-captured from the live 0.5.0 console
(1440 px, light theme) with IPs and local paths masked in the DOM before capture.

## Upgrade notes

### From 0.5.0 (optional)

No config migration, no chown, no restart required. Existing 0.5.0 containers keep
running; 0.5.1 changes only the installer, the doctor check and docs.

```bash
docker compose pull && docker compose up -d
docker compose exec -T rui rui doctor   # the new models row should be PASS
```

### Fresh installs

Use the 0.5.1 pinned installer; it now fails loudly if the ASR/VAD/wake models could not
be fetched, and `rui-healthcheck` plus `rui doctor` agree on the result.
