# rui 0.8.9

**2026-10-29** · [完整 changelog](../../CHANGELOG.md) · 插件不变（dot2 1.3.5 / xiaoai 0.2.3），
`rui_compat` 不变（`>=0.8.1 <0.9.0`）· **本版只发版本，不部署**（部署由 9哥 单独决定）。

0.8.9 只做两件事：把 48 kHz 采集路径上的抽取器改成多相实现（CPU 降下来，语义不变）；
让 8ch/48k 设备默认跟随 manifest 的原生率，16k 降级为「显式省带宽」选项。
无协议变更，`rui-xiaoai-bridge`、`rui-dot2-bridge` 零改动。

## 改了什么

1. **多相抽取（Decimator，48k 路径）**：48-tap FIR 按 `factor` 拆相位，只对输出样本做
   乘加，不再对每个输入样本卷积。
   - **语义与 0.8.8 逐样本一致**：独立 oracle 覆盖 factor 2/3/4/5 × ch 1/2/7/8 ×
     多帧/非整除尾帧，worst `|diff|` **2.98e-7**（浮点求和顺序差异，非行为变化）。
   - **16k / `factor == 1` 不变**：不构造滤波器（`fir is None`），输出与
     `block.astype(np.float32)` 逐样本相等；该路径行为与 0.8.8 完全相同。
   - **离线性能**（10 s / 8 ch / 48 kHz / 20 ms 帧，M2 Ultra）：旧全速率 **0.0965 s**
     → 多相 **0.0263 s**（8 ch，**3.66×**）/ **0.0352 s**（生产 7 列 = 6 mic + ref，
     **2.74×**）。gate「10 s 音频 ≤ 0.2 s」PASS；`--seconds 30` 归一化到 0.6 s 同样 PASS。
   - 复现：`uv run python scripts/bench_decimate.py`；剖面与口径见
     [`docs/analysis/decimate-profile-0.8.9.md`](../analysis/decimate-profile-0.8.9.md)。
2. **8ch/48k 默认跟随 manifest 原生率**：`src/rui/config/template.yaml` 与
   `config.example.yaml` 不再写 `audio.capture.rate`，`effective_audio()` 直接采用插件
   manifest 的 `audio_defaults.capture.rate`（LX06 = 48000，Dot 2 = 16000）。
   - 真实模板 + lx06 manifest → **48000**、`conflicts == []`；dot2 manifest → **16000**、
     无 `capture.rate` conflict；显式 global 16000 + lx06 → **16000** +
     `kind: negotiated`（文案未变）。
   - **显式 16k 仍然可用**（0.8.8 行为保持，不做强制改写），但设备端会自己做
     48k→16k 重采样：语言带能量实测约 **−15 dB**，后果是 **ASR 空转/超时**。
     **唤醒照常成功**，所以「能唤醒」不能证明这条没踩。16k 从此是显式省带宽选项。
   - 文档：[`docs/audio-pipeline.md`](../audio-pipeline.md) 的「wire 率：48 kHz 还是
     16 kHz（0.8.9）」、[`docs/known-limitations.md`](../known-limitations.md) L27。

## 验证证据

- **全量单测**：`uv run pytest -o addopts="" -q` → **2165 passed, 6 skipped**
  （基线 HEAD `6488387`：2136 passed, 6 skipped；净增 29 条）。
- **Lint**：`uv run ruff check src tests` → **All checks passed**。
- **bench**（`scripts/bench_decimate.py`，10 s / 8ch / 48k / 20 ms，M2 Ultra）：

  | 实现 | median s | 相对旧 |
  |---|---|---|
  | 旧全速率（8 ch） | 0.0965 | 1.00× |
  | 多相（8 ch） | 0.0263 | 3.66× |
  | 多相（7 ch = 生产） | 0.0352 | 2.74× |

- **独立 oracle**：worst `|diff|` 2.98e-7；`factor=1` 时 `fir is None`、输出与
  `astype(float32)` 逐样本相等。
- **协商语义测试**：真实模板 + lx06 → 48000、`conflicts == []`；dot2 → 16000、无
  `capture.rate` conflict；显式 global 16000 + lx06 → 16000 + `negotiated`。

## 升级 / 部署注意

- **现网配置不会自动改。** `/config/config.yaml` 里如果仍显式写着
  `audio.capture.rate: 16000`，升级到 0.8.9 **不会**帮你删掉它，16k 会继续生效
  （连同上面那 ~15 dB 和 ASR 空转）。要吃到 48 kHz：**删除该键**（或改成 `48000`），
  然后重启音频平面。
- **已经手工切到 48 kHz 的现网机器**（生产 NAS，9哥 真机手工配置）升级后不需要再动配置；
  上面那条只针对仍显式写着 `rate: 16000` 的部署。本 release 不改部署。
- **本版不部署**：是否上线、什么时候上线由 9哥 单独决定；本 release 只发版本。
- 回滚/升级只涉及 rui 镜像/版本，**两个桥仓无需改动**。

## 未做 / 边界

- **CPU 口径别过度宣称**：多相化只解释抽取器本身（48 kHz 路径上约占单核 0.3%，旧约
  1%）。生产从 16k 换到 48k 多出来的 **+2 核**里，其余归属**未**在离线证实——
  剖面文档已写明，不要读成「CPU 已解决」。
- **真机验收目标**（发布后由 9哥 决定是否部署；**本 release 未验证**）：
  living 平面 ≤ 0.6 核、容器 ≤ 130%、NAS load < 3、`asr_done` ≤ 250 ms；
  唤醒 admit ≤ 500 ms、播歌时 KWS 不回归。
- 不改 barge / AEC / 音量 / followup / 播放语义；不改前端；不加依赖；不动协议。
