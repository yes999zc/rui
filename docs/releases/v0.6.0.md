# rui 0.6.0

**2026-10-26** · [Full changelog](../../CHANGELOG.md) · [Compare v0.5.3...v0.6.0](https://github.com/yes999zc/rui/compare/v0.5.3...v0.6.0)

The device-agnostic core. rui no longer names a speaker: the LX06 adapter is a plug loaded
through the same manifest as the Dot 2, the core audio defaults are neutral, and each device
declares its own hardware in its manifest. Every output — replies, goodbyes, reminders, music,
stop, volume, LED — is routed to a room instead of to a default speaker.

## Highlights

### 1. The LX06 is a plug, and the core names no device

plugs/xiaoai ships a plugin manifest and a rui-device/v1 manifest; the image copies it to
/opt/rui-plugins and the core imports it from its runtime.entrypoint exactly like the Dot 2.
`adapter: xiaoai` keeps working through a single alias (src/rui/adapter_aliases.py, gone no
earlier than 0.7.0), so existing installs migrate with no config edit. src/ and web/ no longer
mention xiaoai outside that alias.

### 2. Three-layer audio, declared by the device that needs it

Manifests gain `audio_defaults` (capture, playback, ack_echo_ignore_ms). The effective audio
is device default < global config < devices[].audio; the core defaults are neutral
(16000/1ch/0ref, earcon ack) and the LX06 manifest states the 48000/8ch/6mic/2ref the core
used to hard-code. save_config only persists what the file already stated or what an operator
changed, so a console save cannot freeze a neutral layout over a plug.

### 3. Every output has a room

The session and its LED follow the turn's room; reminders go to multi_device.default_output
(else the most recently active room); music starts where it was asked and transport commands
follow the output owner; stop only releases the owner from its own room; /debug/say, /debug/play,
/debug/led and volume accept a device. The console shows each device's effective capture,
playback, AEC and cue window.

### 4. The wizard asks which device you have

No device is preselected. With one installed plug it auto-selects; with several the API
returns 409 plug_required and the console renders a first "choose a device" step. New devices
write the manifest's device id; old configs resolve through the alias.

## Upgrade notes

### From 0.5.x

- Config: no edit required. One restart is enough; `rui doctor` gains `audio_rates`,
  `console_token` and the channel-gateway row.
- Mixed houses (LX06 + Dot 2): the global `audio.capture` still wins over a plug's manifest
  defaults, so state the Dot 2 layout explicitly — see docs/deploy.md §3.7. The same applies
  to `ack_echo_ignore_ms` (Dot 2 wants 2500 ms).
- Downstream plugs: raise `rui_compat` to `>=0.6.0 <0.7.0` and declare audio_defaults;
  rui-dot2-bridge 1.2.0 is the reference (plug-test 15 PASS / 0 FAIL / 2 WARN / 5 SKIP).
