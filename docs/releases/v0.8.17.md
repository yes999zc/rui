# rui 0.8.17

**2026-11-02** · [完整 changelog](../../CHANGELOG.md) · 插件不变 · `rui_compat` 不变（`>=0.8.1 <0.9.0`）

0.8.17 是**架构收口**：这一版把 0.8.16 为「小爱在场」设计的默认值全部退回中性，并把部署姿态写成
「**Dot-only**」。

> ### ⚠️ 维护状态变更：作者不再维护小爱（LX06 / xiaoai 桥）
>
> 从 0.8.17 起，**新部署请全面使用 Echo Dot（dot2）**，小爱（LX06 / `rui-xiaoai-bridge`）不再跟进维护。
>
> - 代码与插件**不删、不破坏**：`lx06` adapter、`rui_xiaoai_bridge`、`RUI_ADAPTER_PLUGINS` 中的 `lx06=…`
>   原样保留，已有部署继续可用，`rui_compat` 仍覆盖它们。
> - 不再保证：LX06 侧的行为对齐、新特性适配、现场问题跟进。
> - 原因（2026-11-02 实测）：LX06 的 8 通道采集要靠服务器做 AEC，远场与双讲都劣于 Dot 的设备侧硬件 AEC；
>   客厅切到 Dot 后 0.8.16 里为「媒体声骗过唤醒」而做的声纹门控失去前提。

## 改了什么

1. **默认值退回中性**（0.8.16 的四条副作用项）：
   - `audio.voice.gain_db` 默认 `6.0` → **`0.0`**。+6 dB 的「AEC 后增益」把提示音的回声残差一起放大，
     越过 VAD 门限后被当成用户请求（实测出现 `turn: '在呢。' => '在呢，你说。'` 的自问自答）。
   - `audio.voice.wake_skip_ms` 默认 `0` → **`300`**。0 会让唤醒词自己的尾巴进转写（实测 `turn: '宝。'`）。
   - `audio.voice.empty_wake_cooldown_s` 默认 `120.0` → **`0.0`**。冷却期内真人的唤醒也被丢弃
     （实测把一次真人唤醒锁了 120 s）；需要防误唤醒的部署可自行开启。
   - `ack.keep_overlapping_speech` 默认 `True` → **`False`**（回到「整段切掉 cue 前缀」）。
   - 每一项都仍是**可配置**的：以上只是默认值，`config.yaml` 里显式写回旧值即可。
2. **声纹链路默认不参与**：`speaker_gate` 默认关闭、enroll API 保留但不进默认配置；
   这是给「媒体声能骗过唤醒」的场景留的能力，Dot-only 部署用不上。
3. `uv.lock` 的版本号终于与代码一致（此前一直停在 0.8.14）。

## 与 0.8.15 的行为差别（按默认值跑）

| 项 | 0.8.15 | 0.8.17 |
|---|---|---|
| `vad_max_speech_ms` | 无 | **8000**：超长段按块切，媒体长段不会整段进 ASR |
| `wake_hold_ms` | 1500（固定 1.5 s） | 15000（**上限**，turn 结束即释放）——只对服务器 AEC 的设备生效 |
| per-device `kws_threshold` / `kws_boost` | 无 | 有（`None` = 继承，不配置等于没有） |
| 声纹门控 / 段级门控 / 媒体门控 | 无 | 有，但**默认关闭** |

## 升级与回滚

- 升级：`compose up -d` 换镜像即可；配置无需改动（0.8.16 的键在 0.8.17 仍是合法键）。
- 回滚键：`gain_db: 0`、`wake_skip_ms: 300`、`empty_wake_cooldown_s: 0`、
  `keep_overlapping_speech: false` —— 这四条就是 0.8.17 的默认值，回滚到 0.8.16 行为需要显式改回。
- 已知遗留：`speaker_gate.*`、`empty_wake_cooldown_s`、`keep_overlapping_speech` 仍未进
  `/api/v1/config/catalog`（只能改 YAML 后重启）。
