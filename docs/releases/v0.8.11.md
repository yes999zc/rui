# rui 0.8.11

**2026-10-30** · [完整 changelog](../../CHANGELOG.md) · 插件不变（dot2 1.3.5 / xiaoai 0.2.3），
`rui_compat` 不变（`>=0.8.1 <0.9.0`）· 镜像 digest 由 tag 的 docker-publish 产出后回填（见文末
`<!-- digests -->`）；**发布时生产仍是 0.8.10**，实际 `up -d` 在本文定稿后由本会话静音执行，
部署结果与验收回填到 `docs/HANDOFF.md`。

0.8.11 的主题是「身份、清单、画面都变成部署者能决定的事——但版本号不能」。三块新能力：
身份文案里可以写版本号（值只能来自代码）、HA 实体清单从「全量注入」变成四个配置项、
新增 `local.look` 让助手真的能看一眼摄像头。同批修掉 0.8.10 现场暴露的两件事：命名的场景
（`scene.turn_on`）可以执行，不再是 scene 域一律拒绝；多实体批量控制分批发送 + **回查后**
如实报「部分成功」，不再把 20+ 实体的失败说成「全都没关」。无协议破坏性变更，两个桥仓零改动。

## 改了什么

1. **A 身份占位符（`{version}` / `{config_version}`）.** `assistant.persona` 与
   `assistant.system_prompt` 都支持 `{version}`（= `rui.__version__`）与 `{config_version}`
   （= 配置格式版本），与既有的 `{name}` / `{max_chars}` / `{long_chars}` 同一份映射渲染；
   手写花括号（如 `{"a":1}`）仍原样保留。默认 persona 改为「你是家里的小助理，叫{name}，
   跑在 rui {version} 上（家里自建的语音服务，不是 Home Assistant）。不知道就说不知道，
   别装懂。」——**明确说清它是跑在 rui 上，不是 Home Assistant**。默认 system prompt 追加
   歧义规则：用户问「你是谁 / 你是什么系统 / 版本是多少」时，说的是**你自己**（rui 的版本），
   不是 Home Assistant；提到 Home Assistant 的版本时必须明确说成它的版本。另加一句
   「你自己就是客厅那台音箱，不要把你自己当可控制设备」。老配置（无占位符）行为不变；
   `PUT /api/v1/config` 改文案后下一轮即生效，不用重启。
2. **B HA 清单四配置项.** `tools.ha.context`（默认 `true`）、`context_domains`
   （默认 `["light","switch","cover"]`）、`entity_cap`（默认 `120`，1–1000）、
   `context_exclude`（正则列表，默认空，匹配实体名**或** entity_id，`re.search`、
   大小写不敏感，非法正则在校验期报错而不是运行期崩）。过滤顺序固定「域 → exclude →
   cap」；取数预算按 cap 的 3 倍（200–1000）放宽，避免被排除项吃掉上限；注入文本仍带
   「[不可信外部数据]」标记与既有清洗；每轮日志打印 `fetched N / injected M`；缓存带
   domains 指纹，改配置立即生效。生产实测 75 条 / 4121 字，按本批部署配置的 exclude
   预期降到 ~43 条 / ~1796 字（整份 prompt 5007 字 → ~2700 字）。
3. **B2 场景白名单 + 批量控制如实上报.** 新配置 `tools.ha.allowed_scenes`（默认空）：
   每项必须是 `scene.<lowercase_digits_underscore>` 的 entity_id，匹配用 **entity_id 精确
   相等**（friendly name 只用于注入展示）；`lock` / `alarm` / `valve` / `script` /
   `automation` / `shell_command` / `python_script` / `hassio` 仍一律拒绝。白名单场景单独
   成段注入清单（**不受 `context_domains` 影响**，仍以「[不可信外部数据]」开头），
   `local.ha_call_service` 的说明也引导「关灯/回家这类组合动作优先 `scene.turn_on`，
   逐个实体是退路」。多实体控制改成每批 ≤8 个串行发送，单次预算新配置
   `tools.ha.call_timeout_s`（默认 `10.0`，2–60），总预算 `call_timeout_s × 1.5`；批次失败
   后**先回查受影响实体状态再说话**：全生效 → `ok`；部分生效 → 新状态 `partial`
   （`ok_count` / `total` / `failed`，话术「只做成了一部分：{total} 个里有 {ok_count} 个照做了，
   {failed}没成功，别当成全好了。」）；全未生效 → `unreachable`；**回查失败** → 保守报
   `partial`，绝不报 `ok`、也绝不声称「全都没关」。单实体路径不变。
4. **C `local.look`：看一眼摄像头.** 新只读工具，参数 `question`（可空）与 `camera`
   （留空 / `书房` / `这里` = 本机 USB；配置过的别名 = 对应 HA 摄像头；也接受 `camera.xxx`
   实体 ID）。**USB = 现场抓一帧（实时）**，走 `GET {tools.vision.usb_snapshot_url}`；
   **HA = `camera_proxy` 的最近一帧**，走
   `GET {tools.ha.base_url}/api/camera_proxy/<entity_id>`（token 复用既有
   `tools.ha.token_env`，不新增凭据）。别名 → entity id 的映射写在
   `tools.vision.cameras`（默认空）。图在内存里转 base64 data URI 交给**现有** LLM 链路
   （不新建 HTTP/供应商栈、不动对话路径），要求 1–2 句中文、≤80 字，提示词写明「只描述看到
   的，看不到就说看不到，不要编」。回复用短语区分「现在（实时）」与「最近一次（HA 代理）」。
   **约束**：单帧；一次 look 的**总预算** `tools.vision.timeout_s`（默认 15 s，取图 + 描述
   共用，不是每环节一份）；全局限频 `tools.vision.cooldown_s`（默认 1 次 / 10 s，用
   `time.monotonic()`）；**不落盘**（不写 data 目录、不写 `/tmp`、不缓存、不录像，8 MB 上限）；
   工具自身日志只记「设备名 + 字节数 + 耗时(ms)」，不记 base64 / 画面内容 / 用户的问题。
   **失败话术全在 `session/phrases.py`，工具内零中文硬编码**：没配 USB 快照服
   「书房那台摄像头还没接上。」；取不到图（非 200 / 超时 / 非 `image/*` / 空 body /
   >8 MB / HA 地址空 / 别名未知）「这台现在看不到画面。」；图拿到了但描述失败（厂商报错 /
   预算超时 / 空回复 / 没有可用 provider）「画面看到了，但没描述出来，等下再试。」；
   冷却期内「刚看过一次，等一下再看。」。工具永不抛异常，任何失败都是「一行日志 + 一句话」。
5. **C2 `scripts/usb_snapshot_server.py`：Mac 侧快照服务.** 因为 rui 跑在 NAS 容器里读不到
   Mac 的 USB，所以交付一个 Mac 上常驻的最小服务：单文件、只用标准库，
   `ffmpeg -f avfoundation` 抓单帧走 stdout 管道（**同样不落盘**），
   `GET /snapshot.jpg` → `200 image/jpeg`（带 Content-Length）；抓帧失败/超时 → `503` +
   一行原因（不含本机路径/凭证）；其它路径 404。默认 `127.0.0.1:8766`（本机 8765 已被其它
   常驻服务占用，可用 `--port` 覆盖），参数 `--host --port --device --size --ffmpeg
   --timeout`，默认 device `0`、size `1280x720`。**没有鉴权**：只绑本机或内网，不要暴露
   公网。用法与 launchd 常驻见 `docs/usb-snapshot.md`。
6. **小修 `/api/v1/debug/tool` 按 `spec.name` 或 `llm_name` 解析.** `runner._handlers` 的键
   是 `spec.llm_name`（`local.look` → `look`、`local.music_play` → `music_play`），0.8.10
   用注册名调用会被判 `404 no such tool`——正是本地自检与静音验收要走的那条路。现在两种名字
   都能解析到 handler 与渲染名，真不存在的名字仍 404。

## 版本号不可配置：为什么不做成配置项

`{version}` 只能来自 `rui.__version__`，配置只决定文案里**哪里**出现版本，**没有任何可写的
version 字段**。这是有意取舍：

- **避免对外撒谎**：版本能写进配置，就有人写成 0.9.0 或忘了改；用户问「版本是多少」时，
  答案会与真正在跑的代码不一致——那比没有版本更糟。
- **避免升级后漂移**：本项目的身份文案是部署者自写的，一升级还要记得手改配置里的版本，
  迟早漂移；`{version}` 让身份句与构建号自动同步。
- **`{config_version}` 同理**：它是配置格式版本（`Config.version`），由加载器决定，
  也用于排查「配置是老格式还是新格式」，同样不能让人手填。
- 因此：`AssistantConfig` 里**没有** version 字段，`cfg.version` 仍然只是配置格式版本，
  两者不许混用（有测试守着，`tests/test_config_identity.py`）。

## 隐私与数据边界（`local.look`）

- **画面会离开本机**：这一帧以 base64 的形式发到配置的大模型端点，默认部署是
  **`api.deepseek.com`**。一次「看画面」= 一次云端视觉调用。
- **兜底链也会收到同一帧**：`providers.llm.chain` 配了多个 provider 时，主用失败后下一家
  拿到的是同一张图（都是你自己配的端点），链越长画面去的地方越多。
- **不想出网就换端点**：把 `providers.llm.chain` 指向本机的 OpenAI 兼容视觉服务即可，
  链路不用改。
- **本机不留图**：内存里取图（8 MB 上限）→ base64 → 用完即弃，不写 `data_dir`、不写
  `/tmp`、不缓存、不录像。
- **日志**：工具自身只有 `设备名 + 字节数 + 耗时(ms)`。注意框架层既有的工具调用日志
  （`session/turn.py`）仍会记一行参数与渲染后的回复——这是所有工具一致的全局行为，
  想只看本工具日志请按 logger `rui.tools.look` 过滤。
- **限频**：默认 1 次 / 10 s（全局）本身就是保护：摄像头对着私人空间，且每看一次都要付一次
  云端调用。
- **快照服务无鉴权**：`scripts/usb_snapshot_server.py` 默认只绑 `127.0.0.1`；跨机接必须
  `--host 0.0.0.0` 时请限制在内网，**不要暴露公网**。

## 兼容性与升级

- **无协议破坏性变更**：新增的是配置键、工具、短语与新状态 `partial`；插件契约不变，
  `rui_compat` 仍是 `>=0.8.1 <0.9.0`。
- **两个桥仓零改动**：`rui-xiaoai-bridge`、`rui-dot2-bridge` 不需要动；插件不变
  （dot2 1.3.5 / xiaoai 0.2.3）。
- **老配置可直接跑**：`tools.ha.*` 四个新键、`tools.ha.allowed_scenes` /
  `call_timeout_s`、`tools.vision.*` 都有默认值。
- **唯一的默认行为变化（有意）**：清单默认只列 `light` / `switch` / `cover`，不再列
  `scene` / `script`——这两个域本来就调不动（0.8.11 起 scene 只走白名单），列出来只会诱导
  模型去调一个必然失败的域。想要旧清单就显式把 `context_domains` 写全（scene 仍受白名单
  约束）。
- **升级后不会自己删数据**：`allowed_scenes` 默认空 = 与 0.8.10 一样拒绝一切 scene 调用；
  想用命名场景必须由部署者显式写白名单（本批生产配置写 5 个）。

## 部署清单

**前提**：生产当前是 **0.8.10**（`/health` = 0.8.10，config_version 3）。部署全程**静音**：
`pull` / `up -d` 本身不出声；部署后只做静音项验收。

1. 备份 `/vol1/rui/config/config.yaml`、`plugins/`、`rui-dot2-override.yml` 与当前镜像摘要
   （`*.bak-<ts>` 命名，记进 `docs/HANDOFF.md`）。
2. `rui-dot2-override.yml` 的镜像换成 0.8.11 index digest（见文末）。
3. 查一眼定时提醒队列（避免重启窗口里念出提醒），然后
   `docker compose -f docker-compose.yml -f rui-dot2-override.yml pull && up -d rui`。
4. 写本机配置（上一节六项，写前备份），再 `up -d rui` 一次让配置生效。
5. 按下面清单逐项核对；任一红即回滚（见回滚锚）。
