# rui 0.5.3

**2026-10-25** · [Full changelog](../../CHANGELOG.md) · [Compare v0.5.2...v0.5.3](https://github.com/yes999zc/rui/compare/v0.5.2...v0.5.3)

0.5.3 is the stabilization release for the first multi-device production install: one LX06
and one Echo Dot 2 in the same house, two audio planes, one wall clock. Every fix below was
measured on that install, and each one has a regression test. There is **no config-schema
break** (one nullable per-device field is added) and no plug-contract change.

## Highlights

### 1. A device's own audio settings are the ones that play

The audio plane read the *global* `audio.playback.rate` in the playback path, so a device
override (the Dot 2 wire is 48 kHz mono, the LX06 is 16 kHz) was raised at speak time: the
turn completed, the ring showed `speaking`, and nothing came out. The play path, the wake
cue and the pacer now all use the device's effective audio, and the pre-rendered cue is
resampled instead of relabelled.

### 2. The house-wide session speaks in the room that spoke

A session is house-wide (one turn, one owner), but its voice is not: the idle goodbye and
the LED used the *primary* client, so the LX06 said farewell for a Dot 2 turn in the
bedroom. Session speak / LED / stop now follow `turn_device`, and a new wake cancels the
goodbye instead of racing it.

### 3. The goodbye can no longer lock the house

`turn_open` is what stops a second room from stealing a running turn. A goodbye that landed
between wake detection and admission disarmed the new wake gate, so the admitted wake never
produced an utterance, `on_wake_idle` never ran, and `turn_open` stayed true: every later
wake was rejected until the container restarted. The idle loop now skips while a wake is
in flight or a turn is open, and clears `turn_open` after the goodbye as a safety net.

### 4. A device can declare a longer wake-cue echo window (partial)

A device with hardware AEC still leaks its own tail: the Dot 2 turned its own `在呢。` into a
request and the reply was `怎么了？`. `devices[].audio.voice.ack_echo_ignore_ms` lets one room
override the global `ack.echo_ignore_ms` (the Dot 2 uses 2500 ms), and the goodbye now sends
`reply_finished` so the plane arms its post-playback mute like any other answer.

**Known limitation, fixed in 0.5.4:** on the RUI-KWS path the gate *buffers* the audio inside
the echo window and replays it when the window lifts (that is how a request spoken right after
the cue is preserved), so the device's echo tail can still be replayed as a turn. The knob
narrows the window but does not remove the replay. A cue-time microphone mute on the device
side (adapter) is the design that closes it; until then a Dot 2 install should also keep
`post_playback_mute_ms` at 2500 and expect an occasional self-turn after a wake.

### 5. Doctor answers the three questions this install asked

- `audio_rates`: every device's wire rate against its effective `playback.rate`;
- `channels`: the channel gateway's last error (a Telegram 409 from a second poller is
  exactly what bit this install),
- `console_token`: `console-token.txt` against `web.auth_token`, with the one-line fix.

## Upgrade notes

### From 0.5.2 (recommended for any multi-device install)

No migration. Adding `devices[].audio.voice.ack_echo_ignore_ms` is optional; devices without
it keep the global `ack.echo_ignore_ms`. One restart is enough:

```bash
docker compose pull && docker compose up -d
docker compose exec -T rui rui doctor   # audio_rates / channels / console_token are new
```

### Multi-device installs

Per-device `playback.rate` is now honoured, so the global value can stay whatever the first
speaker needs. `docs/deploy.md` gained the full template (rooms, per-device rate/AEC/mute,
`max_planes`, `default_output`, and one bot per poller).
