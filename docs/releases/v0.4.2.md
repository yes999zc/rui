# rui 0.4.2

**2026-10-25** · [Full changelog](../../CHANGELOG.md) · [Compare v0.4.1...v0.4.2](https://github.com/yes999zc/rui/compare/v0.4.1...v0.4.2)

0.4.2 is the Phase 4 cleanup that closes the console information-architecture refactor.
Navigation now has **one source of truth** in the backend panel manifest, the seven
compatibility-only panels and their redirects are retired, and the README is much
slimmer. There is no config migration, no schema change, no audio/runtime change and no
`/api/v1/*` path change: this is a console-and-docs release.

One deliberate break: **old panel bookmarks no longer redirect**. That is the end of the
one-release compatibility window announced in 0.4.0, and the mapping below shows where
each task lives now.

## Highlights

### 1. One navigation manifest

The console used to derive navigation from three places: the backend panel `group`,
a frontend id→group map, and an i18n title-override table. They could drift — the IA
audit found the rail and the page kicker disagreeing for Logs.

Every `PanelSpec` from `GET /api/v1/panels` now carries:

```json
"nav": {"section": "run | configure", "order": 10, "hidden": false, "icon": "gauge"}
```

The rail and the page kicker read that object directly. `web/src/nav.ts` keeps only the
two section headings and the three hand-written utility destinations (channels,
diagnostics, first-run setup); there are no id→group maps or title overrides left. A
panel the frontend has never heard of is placed by the backend instead of being guessed
into "configure", and the nav icon contract is checked against the shell's `AppIcon`
vocabulary in the panel tests.

### 2. Eleven panels, seven retired — and old panel URLs are intentionally gone

The compatibility-only declarations `assistant-session`, `speaker`, `devices-admin`,
`tools`, `mcp`, `foundation` and `phrases` were removed after their one-release
window in 0.4.0/0.4.1. Eleven panels remain (one hidden), and every task they used to
own is on a merged destination:

| Removed URL(s) | Use instead |
| --- | --- |
| `/panel/assistant-session`, `/panel/settings`, `/panel/phrases` | `/panel/voice-assistant` (reply / phrases tabs) |
| `/panel/speaker`, `/panel/devices-admin` | `/panel/devices` (audio / manage tabs) |
| `/panel/tools`, `/panel/mcp` | `/panel/integrations` (builtin / MCP tabs) |
| `/panel/foundation` | `/panel/system` |
| `/panel/credentials`, `/secrets` | unchanged (write-only credential ledger) |

Old `/panel/<legacy-id>` URLs now render the console's **"No such panel"** state with a
link back to the overview. The removed top-level aliases (`/overview`, `/devices`,
`/logs`, `/assistant`, `/settings`, `/voice`, `/models`, `/tools`) fall through the
SPA catch-all to `/panel/overview`. This is intentional; update bookmarks.

### 3. Providers page renamed to "Models & voice services"

The panel titled "外部资源 / Providers" is now **"模型与语音服务 / Models & voice
services"**, matching the wizard step and what the page actually contains (the LLM, ASR
and TTS chains). The id `/panel/providers` is unchanged, so links and the API contract
do not move.

### 4. A slimmer README

The homepage drops from **512 to 366 lines**. Install, wizard, parameter-provenance and
troubleshooting detail already live in [`docs/first-run.md`](../first-run.md), so the
README now keeps the short path: what it is, screenshots, 30-second start, first run,
features, architecture, status, limitations and the docs index. Screenshots are
deliberately unchanged for now and will be refreshed with the next content pass.

### 5. Multi-device and satellite design, written down

[`docs/multi-device-design.md`](../multi-device-design.md) is a **design-only**
proposal for the next step: what the current 0.4.1 code actually does (one audio plane
drives one device), why "primary speaker" is not required, how rooms and same-word
double wakes should arbitrate, four implementation options, a recommended hub-arbitration
design with one audio plane per device, a `config v3` sketch, a phased plan and the
decisions that need an owner. No runtime change ships with it.

## Upgrade notes

### From 0.4.1 (recommended)

No config migration, no chown and no schema change. Pull and recreate:

```bash
docker compose pull && docker compose up -d --force-recreate
docker compose exec -T rui rui-healthcheck
```

This release touches the console and documentation only. Audio, providers, music,
devices and the config format are unchanged.

### Bookmarks

Old panel URLs now show "No such panel" — use the table in highlight 2. If you want a
soft landing, the not-found page has a button back to the overview. Top-level legacy
paths such as `/tools` resolve to the overview through the SPA catch-all, not to their
old page.

### API

No `/api/v1/*` path was renamed or removed. `GET /api/v1/panels` has one additive
change (`nav` on each panel) and one list change (the seven retired ids are no longer
returned). Integrations that enumerate panels should read `nav` for placement and
tolerate a smaller panel list.

### Rollback

The config is unchanged, so a 0.4.1 image can run the same data directory. Rolling back
also restores the legacy redirects, so old bookmarks work again.
