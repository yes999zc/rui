# rui 0.8.7

**2026-10-29** · [完整 changelog](../../CHANGELOG.md) · 插件不变（dot2 1.3.5 / xiaoai 0.2.3），
`rui_compat` 不变（`>=0.8.1 <0.9.0`）· **本版部署生产**（9哥 授权，做完即测）。

0.8.7 把「私有音源」和「笑话/谜语」做成公版能力，并修掉待机时两处与实际不符的行为：
静音窗口不再打印满刻度 `0.0 dBFS`，待机 KWS 在没有上行、房间安静时不再逐帧空转。
另外把音乐别名接回主路径，放行打断后的应答型短句。没有协议变更、没有 `rui_compat` 变更、
没有新增第三方/灰区内容源。

## 新增

1. **外部音源钩子（`RUI_MUSIC_SOURCES`）**：不需要改 rui 源码，运维用环境变量注册自己的
   `MusicSource` 实现：

   ```bash
   # docker compose 的 env / .env 里，逗号分隔可注册多个
   RUI_MUSIC_SOURCES="private=my_private_source:make"
   ```

   ```python
   # my_private_source.py（放在 rui 能 import 到的路径/镜像里）
   music_sources_compat = ">=0.8.7 <0.9.0"   # 复用 rui_compat 的版本窗语法

   def make(ctx):                            # ctx: SourceContext（只读）
       return MySource(secrets_path=ctx.secrets_path, cache_dir=ctx.cache_dir, ...)
   ```

   - 内置 preset 优先；未知 id 先查外部注册表，仍未注册才 `ValueError`（API 仍 422）。
   - 五方法 `search/random/favorites/star/resolve` 缺失或不可调用时，报错点名到方法；
     `music_sources_compat` 缺失/不匹配时拒绝加载并给出声明范围与当前版本。
   - import/factory 失败只让音乐层降级为 off + 一条 warning，不让 rui 启动崩溃；
     控制台面板不会假绿。
   - 仓库只放接口与 stub：`docs/music-private-sources.md`、
     `examples/music_sources/stub_source.py`。真实实现永不进 git。
   - 私有源自己读凭据；内部 token 建议走 `MUSIC_SERVICE_TOKEN`（env 或
     `<data_dir>/secrets.yaml`，不进 config 明文）。服务返回的 `duration_ms` 是毫秒，
     构造 `Track.duration` 时 `/1000`（rui 内部按秒）。

2. **`local.tell_joke`**：优先调用自建 joke-svc，失败也永远有话说。
   - 请求：`GET <tools.joke_service_url>/v1/joke?kind=&topic=&pid=`，
     `X-Internal-Token` 取 `JOKE_SERVICE_TOKEN`（env 优先，其次 secrets）；缺失不发头。
   - 谜语两段式：第一次只念题面；用户问答案时模型传 `action=answer`；「不好笑/换一个」
     再调一次 `new`。
   - 可选音频：响应带 `audio_url` 时，rui 下载到 `<data_dir>/tmp/joke_audio_*.wav`
     （10 s、8 MB、SSRF 策略、`wave` + `read_wav_mono` 双校验）再交给音频面播放；
     失败/无 URL 用文本 TTS；文本也没有用内置 20 条。
   - 降级链固定：`audio_url → text → 内置 20 条`；任何失败都是一条 warning（不含 token/URL），
     工具不抛异常、不影响整轮对话。
   - 配置：`tools.joke_service_url`（默认空=不启用外部服务，仍用内置示例）、
     `tools.joke_timeout_s`（默认 3.0）；保存后需重启生效（catalog 标注 restart）。
   - 不认跨机 `audio_path`；服务必须把音频以 URL 暴露，或与 rui 同机可读。

3. **音乐别名接主路径**：`AliasStore.apply` 在 `q.plan()` 之前对音乐请求做最长优先的
   别名改写（语音与控制台共用入口），控制台搜索也传 `NameResolver`。别名文件
   `<data_dir>/music_aliases.json` 创建/修复为 `0640`（见 `docs/music-alias-0.8.7.md`）。

4. **打断后的应答型短句**：播放/暂停中，`行/好/继续/别停/换一首/停止/放吧/听吧`
   按上下文映射到 resume / 保持 / next / stop，不再被「这句话没有点歌动词」拒绝；
   非音乐问题仍拒绝，防回归。

## 修复

1. **`voice peak` 日志**：静音窗口不再打印 `0.0 dBFS`（会被监控误读为满刻度削波）。
   聚合初值改 `-120 dBFS`，只有窗口内确实有语音才打印，文案改为
   `[level] voice peak -20.5 dBFS (active 6 s)`；日志频次仍是每 30 s 一个窗口。
2. **待机 KWS 门控**：无唤醒、无上行且房间安静时挂起 spotter；语音 onset 时回灌
   500 ms preroll 再喂当前帧，唤醒词开头不丢。播放/回合/cue/音乐/续听/device wake
   都保持热，barge-in 语义不变。
   - 默认值：`audio.voice.standby_kws_gate=true`、`standby_kws_db=-60.0`、
     `standby_kws_hold_ms=1000`；改后需重启。
   - 合成数据：30 s 静音 1500 step → 50 processed + 1450 skipped（96.7%）；冷→热那帧
     有一次 ≤26 step 的突发，墙钟检测至多增加这一段。
   - 代价：整段低于阈值的唤醒词会漏；噪声大的房间不省电也不退化；device wake 开启时
     门控永不暂停（零收益，见 `docs/standby-cpu-0.8.7.md` §5.8）。
3. **笑话音频**：`audio_url` 下载后先做 WAV 真可读校验，坏文件回退文本，不再出现
   「turn 跳过 TTS、plane 读不了、用户静默」的情况。

## 未做 / 边界

- **P2 未做**：living 专项 profile（py-spy 火焰图）、待机期 ref 通道退出 AEC 的评估。
  本版不伪造 CPU 数字，真机 CPU/load 在部署后按 `docs/standby-cpu-0.8.7.md` §7 验。
- **B1/B2/B3 未做**：ASR 热词/拼音二次匹配、话术三分（没听清/这是应答/库里没有）、
  known-limitations 条目。
- 不改 `rui_compat`，不动 barge/AEC/音量/followup 语义；不内置任何 QQ/网易/VIP 换源/
  聚合解析；不改前端（面板由 catalog 数据驱动）。

## 部署与验证（本版部署生产）

部署按 `docs/HANDOFF.md` 的 0.8.7 部署段执行：备份 `config/config.yaml`、`plugins/`、
`rui-dot2-override.yml` → 只换 override 的 amd64 digest →
`docker compose -f docker-compose.yml -f rui-dot2-override.yml up -d` 一次。

部署后按四项验（任一红即按回滚锚退回 0.8.6）：

1. **D5 七项**：`/health` `version=0.8.7`、`devices=4`、`device_errors=0`、`warnings=0`、
   registered（dot2/dot2-b/dot2-c/lx06）、四台 running+connected、四台 `audio.say` 有 reply
   且 `error=""`、日志 0 次 `got 16000` / `play ValueError` / `audio_config_mismatch`、
   `followup=3000`、LED 最后 off；5 分钟后 errors 仍 0。
2. **待机 CPU**：静置 5 分钟，容器 CPU 目标 **<20%**、host load **<2**；`voice peak`
   只在有语音时出现，不再恒定 `0.0 dBFS`；`standby: suspended` 日志只应在安静且无上行时出现。
3. **唤醒/播放不回归**：唤醒延迟与 0.8.6 主观/日志对比无明显变慢；播放、打断、
   播放中「下一首」正常；device wake 开启的机器不会出现 suspended（预期）。
4. **音乐**：别名「放点薯条匠的歌」能命中；打断后说「行」继续播、说「换一首」换歌、
   说「停止」停；「今天天气」不会被误播。
