# rui 0.8.16

**2026-11-02** · [完整 changelog](../../CHANGELOG.md) · 插件不变（dot2 / xiaoai 不变），
`rui_compat` 不变（`>=0.8.1 <0.9.0`）· **本版只发版本，不部署**（部署由 9哥 单独决定）。

0.8.16 的主题是**「声纹只做门控」**：D8（不做声纹，只按房间仲裁）改为 D8′。
一天的真机日志（09:04–10:05）证明误唤醒的来源不是「分不清谁在说」，而是**外部媒体**：
孩子看视频时 4 分钟 13 次「在呢」，唤醒后视频里的人声被当命令（09:59:16「属好友。」误触出题工具）。
本版让「不是已注册家人说的话」在唤醒与段级两处被**静默拦掉**，同时把音频链路上另外五条
真机问题（首字被 skip、远场增益、残差级压人声、全局门限、空唤醒连击）一起修掉。

> **声纹不承担身份认证、不是安全边界**（录音回放可绕过），也不做多人同时说话分离。

## 改了什么

1. **唤醒声纹门控**（`audio.voice.speaker_gate.enabled`，默认 **false**）
   - CAM++（sherpa-onnx 2.0.1 自带 `SpeakerEmbeddingExtractor/Manager`，192 维，余弦阈值 0.55）。
   - 唤醒音频与注册库比对；不匹配 → **不播「在呢」、不建 turn、不发 Wake**，
     只记 `wake_rejected["speaker"]` 与 `wake rejected: speaker score=0.41 best=son (threshold 0.55)`。
   - 失败方向：模型缺失 / 库为空 / embedding 失败 / 文件损坏 → **fail-open**（照旧唤醒）；
     本设备无档案 → 回退全库；库非空但维度全不匹配 → fail-open。日志 `speaker gate unavailable`。
   - 回滚：`speaker_gate.enabled: false`（一行回到 0.8.15）。
2. **注册入口 + 控制台「家庭成员」页**
   - `POST /api/v2/speakers/enroll` → `…/commit`、`GET /api/v2/speakers`、`DELETE …/{name}`、
     `GET …/{name}/sample.wav`；注册 1–10 s，复用设备推流，不新增硬件。
   - 存 `data_dir/speakers.json`（键 `(name, device_id)`，原子写 0600，最多 5 人）；
     注册后**不重启即生效**（mtime 热读）。
   - 控制台：注册 / 重录 / 删除 / 播放样本 / 显示相似度；中英双语。
3. **段级门控**（`speaker_gate.segment_gate`，默认 true）
   - 每个 VAD 段在进 ASR 前与「注册库 + 唤醒锚点」比对；不匹配 → 静默丢弃
     （`turn_rejected`、`WakeIdle` 安静关窗、`segment rejected: speaker …` 日志）。
   - `wake_window_ms`（默认 2500，音频时钟）内只认锚点；`mode: any_enrolled` 默认，
     `wake_owner` 可收紧「只有叫醒它的人能接着说」。
   - `vad_max_speech_ms`（默认 8000）：超长段按块逐段判定（9.38 s 的媒体长段会被拒）。
4. **cue 切除只丢纯 cue 前缀**（`ack.keep_overlapping_speech`，默认 true）
   - 与提示音重叠的人声不再被 `[0, cue_end+40]` 整段切掉；日志新增 `overlap_from=`，
     供真机标定 1.6 倍阈值。false 回到旧行为（A/B 用）。
5. **六条小修**
   - `wake_skip_ms` 默认 0（含冷装模板）：300 ms 吃掉「几点了」的「几」（实测 3/6）。
   - AEC 后 +6 dB 人声增益 + 0.95 限幅（`audio.voice.gain_db`），采集增益不动；
     overdrive 观测保持在增益前，新增 `limiter_count`。
   - 残差级旁路跟随整个 turn（`audio.aec.wake_hold_ms` 改为上限，默认 15000）。
   - per-device KWS 门限：`devices[].audio.voice.kws_threshold` / `kws_boost`。
   - 空唤醒冷却：连续第 2 次空唤醒 → 该设备 KWS 命中抑制 120 s。
6. **D8 → D8′**：`docs/multi-device-design.md` 的决策表与变更记录已改。

## 部署前必读（bridge）

1. **存量配置**：0.8.15 的生产 `config.yaml` 里显式写着 `wake_skip_ms: 0`（今天手工改过），
   不需要处理；但**其它机器/新装**若显式写 300 会保留 300。
2. **生产门限**：当前是视频止血态 `:2.00 #0.15`。0.8.16 上线后应回到 `:4.00 #0.07`，
   视频误唤醒交给声纹拦（验收第 1 条就是量这个）。这一步是**部署动作**，不在本版代码里。
3. **声纹注册**：部署后先在控制台「家庭成员」页给 3 人 × 每台要用的设备各录一次
   （每台 3 段 × 3 s）；`speakers.json` 落在 `data_dir`（宿主机 `/vol1/rui/data/speakers.json`）。
4. **开关顺序**：先 `speaker_gate.enabled: true` + 阈值 0.55 观察 `wake rejected/admitted` 两类日志，
   再回门限。若误拒家人，先降阈值，再考虑 `enabled: false` 回滚。
5. **模型**：`/vol1/rui/data/models/speaker/campplus.onnx`（CAM++ 28 MB，dim 192），不随镜像发布；
   缺失时门控 fail-open（日志 `speaker gate unavailable`），不影响唤醒。
6. **内存**：5 台各加载一份 28 MB 模型（约 +140 MB RSS，未实测），部署后看 `docker stats`。

## 验收（真机，9哥 在场；每项带分母）

1. 视频在场 10 分钟：误唤醒「在呢」= **0**，日志有 `wake rejected: speaker`。
2. 家庭三人 3.5 米：唤醒 ≥ **4/5**（门限 0.07），每条有 `wake admitted: speaker score=`。
3. 视频播放中家人说「几点了」×5：≥ **4** 次正确；视频人声产生 **0 个 turn**。
4. 注册：3 人 × 每台设备 3 段 × 3 s；删除/重录后旧 embedding 不残留。
5. 放歌 80%：3.5 米「下一首」×5 ≥ **4/5**；歌本身 10 分钟 **0 次**唤醒；
   `overdrive_count = 0`、`aec_erle_db ≥ 15`（目标 ≥20）。
6. 回归：`wake_skip 0` 下「你好小宝，几点了」不丢首字；`mic 10` 放歌 `overdrive_count = 0`；
   2 米近场 `[seg] peak < 0.95`。

## 已知限制

- 声纹是 UX 过滤，不是身份认证/门禁安全；录音回放可绕过。
- 无参考通道的外部媒体（电视/平板）无法被 AEC 消掉，只能靠声纹拦「谁能下命令」；
  命令音频本身仍被媒体污染，ASR 质量会降。
- 放歌时「下一首」的声学污染只能靠残差级旁路缓解，DTD/AEC3 不在本版。
- 冷却期内该设备**真人唤醒也会被丢弃**（连续空唤醒后的保护），回滚 `empty_wake_cooldown_s: 0`。
- `wake_hold_ms: 1500` 是上限、不是旧固定窗的逐字回滚（turn 提前结束会更早恢复抑制）。
