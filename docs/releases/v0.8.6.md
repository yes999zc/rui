# rui 0.8.6

**2026-10-29** · [完整 changelog](../../CHANGELOG.md) · 插件 **dot2 1.3.5 / xiaoai 0.2.3**，`rui_compat` 不变（`>=0.8.1 <0.9.0`）· **本版将部署生产**（0.8.5 只发 tag/release，生产仍是 0.8.4）。

0.8.6 把 0.8.0 随旧面板系统一起删掉的「通知通道」能力补回 v2 控制台，把首页文案改成不随版本变化，
并把 dot2 数据面 1011 的桥侧计数日志写进可复核的文档。没有协议变更、没有 `rui_compat` 变更，
Channels 页是恢复被删能力，不是新协议面。

## 新增

1. **v2 控制台 `/channels`（通知通道）**：Telegram / 微信两张卡片——`enabled` 开关、
   `reply_mode` 三选（text / voice / both）、白名单 ID 逐个增删（保存时去首尾空白、空行忽略）；
   保存先 `PUT /api/v1/channels`，再 `GET` 回读并显示是否一致。令牌只读：Telegram 只显示
   `token_configured`（在服务端 env/secrets 配置 `TELEGRAM_BOT_TOKEN` / `RUI_TELEGRAM_TOKEN`），
   微信只显示 `logged_in` / `account_id` / `user_id`。
2. **通道网关卡片**：显示 running / stopped / unknown 与最近错误，提供 `start` / `stop` /
   `restart`，busy 时禁用，成功后重取状态。错误文案按上下文分流：网关动作的 503 →「网关未就绪」，
   通道加载/保存的 503 →「服务暂不可用」，422 展示服务端 detail，网络错误保留统一兜底。
3. **配置区入口**：Config 子导航新增「通知通道」/「Channels」（`/v2/channels`），复用 v2 现有
   card / field / theme，不复活 `/legacy` 路由、不引入组件库、不加依赖。
4. **README 三仓通用化**：核心与两个桥的首页不再逐版本罗列，改为项目介绍 + 「Latest release」
   单一版本指针；保留「AI 一条命令接入新设备」入口。
5. **arm64 运行验证**：已发布 0.8.5 镜像在 `linux/arm64` 上可拉取，`ffmpeg` 可执行、
   `rui` + `numpy` 可导入、服务启动后 `/health` 返回 200 且 `version=0.8.5`。只验证运行时层，
   不含 ARM 性能/长时间稳定性结论（见 `docs/arm64-verification-0.8.5.md`）。

## 修复 / 文档

1. **dot2 1011 桥侧计数日志（dot2 桥 1.3.5）**：桥的关闭日志行尾追加
   `close#N interval=…s dropped=N`（纯诊断，keepalive / abort / 重连行为未改）。
   `docs/analysis/dot2-data-plane-1011.md` §10 改用**单一真实事件**作示例
   （§2.2 表 #12：`close 12:16:08 UTC, rx=9329320B, tx=0B, close#12, interval=305.1s`），
   不再把 §2.1 事件 #1 的 rx/tx 与别处的 close 计数拼成一行，并保留字段判读表。
2. **通道页 503 文案分流**：修复此前「任何 503 都显示网关未就绪」。网关动作与通道读写现在
   使用不同文案；`v2.channels.saveFailed` 从死文案变为保存失败标题。
3. **测试**：`tests/test_channels_view.py` 21 条（源码契约 + 真实 `TestClient` 的 PUT→GET 回读、
   `channels.json` 0600、422、503 两条分流、token/微信账号不泄漏；503 用真实 supervisor 缺失状态触发，
   不 mock HTTP 错误）。

## 部署与插件

- **本版部署生产**（0.8.5 只发版未部署）：按 `docs/HANDOFF.md` 部署清单执行——先备份
  `config.yaml` / `plugins/` / `rui-dot2-override.yml`，只换 override 的镜像 digest，随后
  一次 `docker compose -f docker-compose.yml -f rui-dot2-override.yml up -d`。
  tag/release 本身不部署；生产变更以 9哥 批准为前提。
- **插件矩阵**：dot2 bridge **1.3.5**（含 1011 计数日志）/ xiaoai bridge **0.2.3**（本批仅 README）。
  `rui_compat` 保持 `>=0.8.1 <0.9.0`，C-001 不变。
- **回滚**：任一验证项红 → 换回上一镜像 digest + `up -d`；配置类先回备份再排查
  （具体 digest/备份名以部署时 HANDOFF 记录为准）。

## 验证

部署后按四项验（任一红即回滚）：

1. **`/v2/channels` 200**：带控制台 token 打开 `/v2/channels`，Config 子导航出现「通知通道」，
   两张通道卡片 + 网关卡片正常渲染，浏览器控制台无报错。
2. **channels API**：`GET /api/v1/channels` 返回 `telegram` / `weixin` / `gateway`；改一项后
   `PUT` 再 `GET` 回读一致，`<data_dir>/channels.json` 权限 0600；网关 `start` / `stop` /
   `restart` 返回预期状态；无 supervisor 时 503 文案为「网关未就绪」而非服务不可用。
3. **插件 1.3.5**：生产插件目录与 catalog 显示 dot2 **1.3.5**；`/health` 的 registered 插件正常；
   1011 日志行出现 `close#N interval=…s dropped=N` 字段（或确认该窗口无 1011）。
4. **D5 七项**：`/health` `version=0.8.6`、`devices=4`、`device_errors=0`、`warnings=0`、
   registered（dot2 / dot2-b / dot2-c / lx06）；四台 running+connected；四台 `audio.say`
   有 reply 且 `error=""`；audio summaries 与 0.8.4 一致；日志 0 次 `got 16000` /
   `play ValueError` / `audio_config_mismatch`；`followup=3000`；LED 最后 off；
   5 分钟后 errors 仍 0、restarts 0。
