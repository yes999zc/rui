# rui 0.5.2

**2026-10-25** · [Full changelog](../../CHANGELOG.md) · [Compare v0.5.1...v0.5.2](https://github.com/yes999zc/rui/compare/v0.5.1...v0.5.2)

0.5.2 closes the two gaps between a new user and a working satellite: the documented
`curl … | sh` install died halfway, and the console's connection test failed every
inbound speaker that runs no SSH (the Dot 2). The audio and arbitration code is
identical to 0.5.1: **no config-schema change, no plug-contract change, no migration.**

## Highlights

### 1. The documented one-liner install finishes again (dot2 #15)

`docker compose exec -T` attaches stdin, and with `curl … | sh` the installer's stdin
*is* the rest of the script. The /health probe therefore swallowed the remaining bytes:
the run printed `healthy`, then `sh: Syntax error: Unterminated quoted string`, exited 2
and never wrote `console-token.txt`. The `rui token` read one block later had the same
shape. Both sites now redirect `</dev/null`; the one-liner is unchanged because it now
works.

Two tests guard it: one runs the shipped `install.sh` from a pipe against a fake docker
that drains stdin (network-free) and asserts exit 0, the closing block, a 0600 token
file and that the token never reaches stdout; a second fails CI if any future
`docker compose exec` forgets the redirect.

### 2. A connected satellite is ready, and the test follows the transport (dot2 #7)

`GET /api/v1/devices/{id}/status` reported `ready=false` + `token_missing` for a device
whose adapter owns the credential (the dot2 plug reads a 0600 file instead of rui's
env/secrets store). A live link is proof that authentication succeeded: the row now
carries `token_managed_by_adapter: true` and stays ready while the speaker is online.

`POST /api/v1/devices/{id}/test` probed every device on `:22`. An inbound speaker dials
in, and the Dot 2 runs no SSH at all, so a healthy satellite always tested red. The host
row is now `not_applicable` for inbound transports (the plane's live link and the
listening port are the evidence), a bounded 3 s wait covers a device that was just saved
or restarted, and the response reports `transport`, `listen_port` and `waited_ms`.
Outbound adapters keep the TCP + SSH-banner probe.

### 3. Console: adding a second speaker

Adding a device prefills `living`, which collides with the main speaker; it now picks the
first free id (`living` → `satellite` → `satelliteN`). The connection test renders
`not_applicable` as N/A, the test note and the host label explain the inbound/outbound
split, and the stale "only one plane (0.3)" notice now names
`multi_device.enabled=false`.

## Upgrade notes

### From 0.5.0 / 0.5.1 (optional)

No migration, no chown, no config edit. Breaking changes: none. The new response fields
are additive; the readiness change only removes a false `token_missing` on a connected
device.

```bash
docker compose pull && docker compose up -d
docker compose exec -T rui rui doctor
```

### Fresh installs

Use the 0.5.2 pinned installer. The piped form in the README is covered by an
end-to-end test, and a model-fetch failure still exits non-zero.
